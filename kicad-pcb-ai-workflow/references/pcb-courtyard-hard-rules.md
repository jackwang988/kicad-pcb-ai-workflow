# PCB Courtyard-First Placement Safety — Native Geometry Preview

This R10 **read-only layout planner** is not KiCad DRC and cannot certify zero DRC errors. A KiCad footprint's F.CrtYd/B.CrtYd boundary is an **assembly courtyard**, not a blanket copper clearance or a guarantee of a correct electrical connection. KiCad native DRC independently checks courtyard overlaps, custom `courtyard_clearance`, copper spacing, hole constraints, zone keepouts and more. The planner must not weaken any effective rule to obtain a candidate. Use the actual `.kicad_pro`, `.kicad_dru`, board, XML netlist, approved fab profile and source-bound placement policy.

## Order and checks

1. **Confirm fabricator profile** using `pcb.fab_preview` / explicit human `pcb.fab_confirm`. Apply actual Board Setup, netclasses, stackup and custom DRC rules via accepted Konnect writer. Run `pcb.layout_preflight` to read back real rules and netlist parity.
2. **Read original native geometry** using KiCad `.kicad_pcb` courtyards. For supported top-side straight-line closed Courtyards, preserve the original polygon, not just its AABB. An accepted native `pcbnew` read-only snapshot may validate the rotation transform; unverified rotated/bottom/multi-outline/curved Courtyards are **BLOCKED**, never replaced by invented rectangles. One footprint's `F.CrtYd` is not necessarily a symmetrical axis-aligned rectangle.
3. **Respect occupancy**: check actual courtyard polygon-to-polygon overlap and extra gap; reserve explicit native footprint-disallow zone polygons; protect locked, connector, RF keepout-anchor and mechanical footprints. Fixed circular NPTH mounting drills are separate mechanical obstacles. Unsupported or movable mounting holes require native evidence before automation.
4. **Respect electrical constraints during search**: use source-declared `fixed`, `corridor`, `pad_proximity` and `decoupling` constraints. For pad rules, validate pad number, current net and actual pad center; verified native pad offsets can support rotated footprints, otherwise only top-side zero-angle pads are accepted. A named GND-return via is checked for real UUID and net identity. Evaluating a distance does **not** prove return-plane continuity, transient inductance or finished copper.
5. **Bound search and preserve state**: try a currently legal position before moving a footprint; generate candidate grid positions lazily with an explicit cap, and evaluate each candidate against currently placed objects. A failed greedy bounded search is `REPLAN_REQUIRED`, not proof that the board is impossible. The later global pass only translates movable modules; no automatic module/footprint rotation is claimed.
6. **Apply and independently verify**: `BOUNDED_MODULAR_PLACEMENT_PROPOSAL` is coordinates only. Exact approved moves through Konnect remain separately accepted, and must be saved/read back, checked against the plan, followed by native KiCad DRC and G3 placement review. During placement, incomplete airwires are expected; distinguish genuine new mechanical/copper violations from intentionally unrouted nets. Never claim that this planner has eliminated all future DRC findings.

## Courtyard clearance semantics

The Skill's `courtyard_clearance_mm` is a **conservative assembly planning gap** between the *already enlarged* Courtyard boundaries, not the copper clearance nor a new global KiCad minimum. An explicit `.kicad_dru` `courtyard_clearance` minimum is additionally read, including `mm`, `mil`, and `in`. The planning gap uses the maximum of the confirmed Skill suggestion and all understood custom minima, regardless of custom condition scope. This is conservative, not necessarily KiCad's exact conditional rule evaluation. An unrecognized custom expression blocks planning and requires actual native review. If effective Courtyard-overlap DRC severity is explicitly set to `ignore`, preflight refuses to interpret that as acceptable.

## Current limits and no false approvals

- Existing `placement_review.py` remains the independent G3 auditor, using native pad positions where supported. Its `critical_subcircuits`/visual/thermal/routing/review receipt requirements are not waived. Other critical-subcircuit types still need actual current G3 knowledge and review.
- Native outline support is currently a rectangle or an exact four-edge axis-aligned rectangular loop. Arbitrary board outlines, internal slots, complex Courtyards, and 3D enclosure collisions require a richer native geometry model and/or mechanical acceptance. Unknown means stop, not ignore.
- Only straightforward polygonal footprint Keepouts and fixed circular NPTH drills are screened. Copper-to-pad/track clearances, solder mask/silk, holes with other geometries, and actual routing congestion still require real KiCad native checks. The planner uses **supported constraints**, not a full replication of KiCad's DRC rule engine.
- No actual board is edited by `pcb.layout_plan`. There is **no general accepted Konnect auto-placement execution/rollback loop** in this preview. Successful offline synthetic tests are not real Windows KiCad/Konnect validation.
