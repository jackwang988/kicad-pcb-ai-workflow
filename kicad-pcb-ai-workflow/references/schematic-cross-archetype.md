# Three-Pass Schematic Design and Cross-Archetype Validation

**Pass 1 — Topology:** Establish the exact pin-to-net graph, power tree, interfaces and manufacturer-backed reference circuits independently of page coordinates. **Pass 2 — Composition:** Select appropriate page archetypes, place modules and symbols with reserved wiring corridors, hierarchical ports and clear value/designator labels. **Pass 3 — Native verification:** Draw/read actual KiCad wiring; export XML and ERC, inspect complete page renders, locate ambiguous nets or labels, and obtain engineer review.

Test the method against different project archetypes rather than generalizing from one ESP32 demo: power conversion, clock/reset, RF/matching, dense MCU, analog interface, high-speed connectors and hierarchical/multi-unit designs. Source and tool conditions must be recorded. A test passing for a simple page does not grant acceptance of untested geometry or KiCad backend features. See [topology rules](schematic-ai-layout-rules.md).
