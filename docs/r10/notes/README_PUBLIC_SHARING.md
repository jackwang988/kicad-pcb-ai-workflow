# KiCad PCB AI Workflow — 分享版使用说明

> 原始来源：`R10.0-alpha.3-local.5`。本文件包在前一脱敏版基础上**额外加入 cache-first-1 器件知识库复用，以及 G1/G2/G3/G4 四阶段缓存优先评审**；原先“只做脱敏不改脚本”的说明适用于此前的纯分享版，不再适用于这个增强版。
> 适用：了解工程化AI Skill的设计方法，以及在本机KiCad项目中按文档逐项配置、检查、验证。

## 一、这是什么？

该Skill把硬件工程中的需求、器件资料、原理图、PCB设计规则、布局评审、布线计划、ERC/DRC、DFX/NPI和制造候选导出串成受控工作流。它包含七个按需读取模块，43个登记的Python工具组件和JSON数据契约；不是无需工程师参与、可以直接保证任意PCB正确的“一键全自动设计器”。

**重要边界**：主线终点为 `DESIGN_PACKAGE_READY_FOR_REVIEW`（设计资料待审核）；真实生产签核、CAM/EQ、样机验证及ECO属于外部任务。`EXPORTED_NOT_RELEASED` 只表示制造候选导出，不是量产授权。

## 本次新增：原理图设计前先复用芯片知识卡

新项目首先运行`device_knowledge.py resolve`查仓库外共享缓存；命中就用`brief`读取已经核对的简短条目。第一次查阅芯片后将已审核资料通过`register`入库供后续项目使用，离线查不到或过期才进行原厂资料更新。完整步骤及命令见`references/device-knowledge.md`。缓存不随公开分享包传播。

## 最新增量：四阶段知识复用和工具分工

- G1：原理图评审读取冻结知识卡，保留当前网表/ERC及人工确认。
- G2：资源锁校验时读取符号、封装和Pinout知识卡，必须核对当前Pin↔Pad。
- G3：布局评审读取去耦、晶振、RF和关键局部知识卡，必须检查真实板上对象及几何。
- G4：最终PCB静态评审读取器件PCB专用卡，必须独立检查铜层/DRC和工程师结论。
- **工具职责**：AI规划，Python计算/审计，经本机验收的Konnect MCP执行实时写入，KiCad原生验证最终结果。离线pcbnew仅在独立候选、写入权已交接时执行。
- **推荐从这里开始**：[完整16节点详细运行规范](references/latest-complete-workflow.md)。

## 二、最简单的学习方法

1. 首先阅读 `SKILL.md`，再读 `references/capabilities.md` 和 `references/design-execution-local.md`。
2. 在支持执行本地脚本的环境中，先进行**只读**模块发现：

   ```bash
   python scripts/workflow.py modules --intent routing
   ```

3. 根据 `references/module-environment.md` 检查本机KiCad、CLI及Python兼容性。推荐基线KiCad 10.0.7；新版10.0.x需单机验证。设备安装差异可影响可用能力。
4. 现有PCB只能先在隔离副本中操作。修改默认预览，需显式授权后才使用 `--apply`；不要直接覆盖原工程。
5. 真实实时PCB修改依赖**独立安装**的Konnect-EDA或经项目验收的其他工具。外部执行器不在这个ZIP包内；请遵循其许可证与官方安装说明。
6. 每次真实操作后保存、重载、运行KiCad原生ERC/DRC并复核工程版本、网络、保护对象和必要人工评审。

## 六、接收者常见疑问

- 复制Skill文件就能直接让AI画板吗？**不能**。需要AI客户端、KiCad及适用的执行后端，且各自需要配置与验证。
- 有没有自动布局和自动布线？当前有审查器、受控布线计划、实验性A*候选及限定后端操作；不等于通用的端到端自动布局布线。
- 能直接将Gerber送厂生产吗？**不能**。必须按实际项目完成设计审核、工厂CAM/EQ和授权。
