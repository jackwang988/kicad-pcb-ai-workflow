# 节点3器件知识库复用增强 · cache-first-1

基础：R10.0-alpha.3-local.5 的前一公开脱敏分享包；这是**独立派生增强版**，非已合并的官方仓库版本，也没有附带器件资料或个人项目。

## 改动
- `device_knowledge.py`：新增 `register`（将过去已审核卡片及实际官方最新版本核验记录写入不可变本地索引）、`resolve`（新项目先离线精确匹配并生成新的requirements，缺失/过期/冲突单独报告）、`brief`（按需提取极小的可信条目）。
- `workflow.py`：节点3新增 `architecture.sources_resolve / architecture.sources_register` 工作流入口，无须先构建全套配置，统一使用工具白名单和项目输入校验。
- `SKILL.md`、器件/原理图流程文档：把“先查库，再查原厂”规定为原理图和芯片替换任务的强制前置流程。
- 新增示例清单、离线合成测试，更新版本与脚本哈希清单，保留原先`audit`和`bundle`及G1/G2/NPI安全约束。

## 验收范围
- 使用纯离线合成资料进行单元测试：索引登记、重复登记、精确命中、错误封装不命中、到期阻断、内容被篡改阻断、未验证卡片不能入库、独立项目冻结和按需摘要。
- 未在这里实际执行KiCad、验证芯片真实数据、联网检测厂商新版或测量真实模型Token消耗。节约Token来自更少全文输入，不保证固定节省比例。

## 注意
- 已有卡片若未登记到registry，先拿**当时已审核的** `device-requirements.json` 执行 `register`，之后才可被新项目自动找到。
- `max_check_age_days` 是明确的本地重查政策，不是厂商发布保证；定稿、关键安全功能和制造放行仍要核查原厂版本。
- 检查通过不等于工程设计通过；新的项目电压、条件、引脚/封装和推荐应用电路仍须G1/G2逐项核对。
- 不自动上传缓存到公网；对外分享仅传播代码和模板，不传播版权受限的PDF及企业内部证明。

## 新增：节点6 G1 复用冻结知识库（G1-cache-first-1）
- 原理图G1评审自动生成经过重新核对的`device-knowledge-brief.json`，按位号、制造商、精确MPN和封装摘要展示核对过的项目冻结卡条目。
- 与原厂文档SHA完全相同时，使用冻结包中`texts/`已有提取文字，不重复PDF文本提取；所有原始资料及图表仍保留并绑定，必要时按需查看。
- G1静态门禁校验摘要与冻结源的一致性，篡改、缺失、过期或冲突必须阻断。
- 未添加联网下载动作；本次纯离线测试不等于真实KiCad设计验证或量化token节省。
